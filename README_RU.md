# AudioText Studio 1.4 — Windows 11

Графическое настольное приложение для **локального** извлечения звука из видео и расшифровки речи.

## Возможности

- Выбор MP4 / MKV / MOV / AVI / WebM / MP3 / WAV / M4A / FLAC и других аудио-/видеофайлов
- Видео → MP3, M4A, WAV (первая аудиодорожка)
- Видео/аудио → TXT с временными метками
- Видео/аудио → SRT-субтитры
- Режимы: «Только аудио», «Только текст», «Аудио + текст»
- faster-whisper с моделями tiny, base, small, medium, large-v3; русский, английский или автоопределение
- Увеличенный журнал обработки (14 строк), прокрутка, выделение текста, Ctrl+A / Ctrl+C, кнопка «Копировать журнал» и отдельное изменяемое окно с полными логами
- Автоматическое сохранение транскрипции после каждого законченного минутного участка; после сбоя можно продолжить с контрольной точки, не повторяя распознанную часть
- Восстановление TXT/SRT из атомарного контрольного файла, защита от дублирования уже сохранённых фраз; сохранение извлечённого MP3/M4A/WAV для повторного использования
- Параллельное распознавание двумя обработчиками по умолчанию, общая очередь 60-секундных блоков; законченные блоки можно сохранять и восстанавливать независимо от порядка выполнения
- Оценка оставшегося времени на основе реальной скорости обработки (появляется после первого блока и регулярно обновляется)
- Режимы производительности: balanced (по умолчанию), quiet (фоновый), fast (максимальная скорость); ручной выбор числа обработчиков и резерв CPU 15–25% (обычно 20%)
- Опциональная локальная диаризация говорящих (pyannote Community-1): автоматическое количество или ровно 2–12 участников, стабильные метки по всей записи
- Отдельный TXT/SRT с именами голосов, переименование через GUI без повторного распознавания, запуск определения голосов поверх готового TXT
- Кэш готовых интервалов голосов на диске — повторный экспорт без повторного запуска модели
- Система голосов использует отдельный Python 3.12 и окружение PyTorch: установка выполняется при первом применении; исходный EXE остаётся компактным
- Состояние, журнал, приблизительный прогресс, кнопка остановки, открытие папки результатов
- Обработка файлов локально, без загрузки ваших медиа в облако
- Не нужен Python после установки готовой программы

**По умолчанию:** `small`, русский язык, CPU/int8. В параметрах выбирается, где запускать Whisper: **CPU — процессор** (`int8`) или **GPU — NVIDIA CUDA** (`float16`). Настройка сохраняется между запусками. При выборе GPU программа не переключается на CPU без вашего решения.

### Подготовка NVIDIA GPU на Windows

**Начиная с 1.2.0:** приложение заранее проверяет наличие `cublas64_12.dll` и `cudnn64_9.dll` в доступных каталогах до извлечения звука. Если DLL не найдены, показывается инструкция, как настроить CUDA, без траты времени на длительный файл.

Для GPU нужны совместимый драйвер NVIDIA и библиотеки **CUDA 12 (cuBLAS)** и **cuDNN 9**. Они **не включены в установщик** и должны быть установлены отдельно и доступны процессу AudioText Studio через расположение DLL или `PATH`. Без них CPU-режим работает как раньше.

1. Проверьте, что PowerShell-команда `nvidia-smi` показывает вашу видеокарту.
2. Установите нужные библиотеки по официальным инструкциям [CUDA 12](https://developer.nvidia.com/cuda-downloads) и [cuDNN 9 для Windows](https://docs.nvidia.com/cudnn/latest/installation/backend/windows/). Убедитесь, что пути к DLL включены в `PATH`; не скачивайте DLL из непроверенных источников.
3. Перезапустите AudioText Studio, выберите **GPU — NVIDIA CUDA** и запустите короткий файл.
4. Если GPU недоступна или отсутствуют DLL CUDA/cuDNN, программа покажет диагностическое сообщение. Вернитесь в настройки и выберите **CPU**.

Проверки CI подтверждают передачу выбранного устройства в `faster-whisper`. GitHub-hosted Windows runner не имеет GPU NVIDIA, поэтому реальную CUDA-обработку нужно проверить на компьютере с CUDA. Производительность зависит от модели и VRAM.

Первая загрузка выбранной модели Whisper требует интернета, затем модель работает офлайн. Модель хранится в пользовательском кеше Hugging Face, не в папке приложения.

## GitHub Actions: автоматический установщик EXE

Отдельная инструкция: **[GET_EXE.md](GET_EXE.md)**. В проект включены скрипт `PUBLISH_TO_GITHUB.cmd` для первоначальной загрузки и workflow `.github/workflows/build-windows.yml` для компиляции на GitHub-hosted Windows. После каждого push в `main` установщик доступен в **Actions → Artifacts**; тег `v1.2.0` дополнительно публикует **GitHub Release**. Компьютеру не нужны Python и Inno Setup, чтобы просто скачать и установить собранную программу.

## Локальная сборка установщика (альтернатива, один раз на Windows)

1. Распакуйте проект в папку без кириллицы, например `C:\AudioTextStudioBuild`.
2. Запустите **`BUILD_INSTALLER.cmd`** двойным кликом.
3. Скрипт использует `Python 3.12` (через `py -3.12`). Если Python отсутствует, установите его с https://www.python.org/downloads/windows/ . Для проверки: `py -3.12 --version`.
4. Если Inno Setup 6 отсутствует, скрипт предложит его установку через `winget` (интерактивно); при необходимости установите вручную с https://jrsoftware.org/isdl.php.
5. По завершении готовый установщик будет в `installer\AudioTextStudio_Setup_1.2.0.exe`.

Сборка может загрузить довольно много Python-библиотек и занимает место на диске. После установки **отдельный Python не нужен**. Папка `dist\AudioTextStudio` содержит также переносимую версию программы.

При использовании GitHub Actions локально собирать `.exe` не требуется: см. `GET_EXE.md`.

Чтобы попробовать интерфейс **без сборки установщика**, можно запустить `RUN_WITH_PYTHON.cmd` (нужен Python 3.12).

### Работа с журналом ошибок

Журнал занимает 14 строк и имеет независимую прокрутку. «Копировать журнал» копирует весь текст в буфер обмена. Можно выделить конкретный фрагмент мышью и нажать **Ctrl+C**, или **Ctrl+A** для выделения всего журнала. Кнопка «Открыть отдельно» показывает журнал в отдельном окне с изменяемым размером; свежие строки автоматически появляются в обоих окнах. Запуск обработки не требуется для копирования уже видимых логов.

## Возобновление после сбоя и выключения компьютера

Начиная с версии **1.2.0**, длинные записи распознаются участками по **60 секунд**. Каждый успешно законченный участок сохраняется в отдельный JSON-checkpoint рядом с результатами (подпапка `.audiotext-checkpoints`). Контрольная точка атомарно записывается на диск. TXT и SRT обновляются после каждого такого сохранения. При внезапном завершении текущий незаконченный участок придётся обработать заново; ранее сохранённые блоки повторно не распознаются.

После перезапуска снова выберите **тот же аудио/видеофайл**, ту же папку результата, модель, язык, опции SRT/VAD и режим обработки. Программа обнаружит сохранённое состояние и покажет **«Продолжить»**. Нажмите кнопку или при запуске обработки выберите «Да — продолжить». «Нет» запускает новую расшифровку, сохраняя прежние TXT/SRT отдельными файлами. Можно поменять CPU на GPU или обратно, не теряя прогресс.

Если обработка была в режиме «Аудио + текст», и ранее успешно извлечённая дорожка ещё лежит в папке результатов, программа использует её повторно. В случае аварии во время **самого извлечения аудио** FFmpeg придётся запустить заново. Восстановление также не переносит checkpoint на изменённый, перемещённый или переименованный исходный файл, а смена модели/языка/других параметров создаёт новую задачу.

TXT/SRT и промежуточные файлы находятся только на компьютере. Программа удаляет checkpoint после завершения работы, но сохраняет результаты. При повреждении файла checkpoint программа сообщает об ошибке, не перезаписывая его автоматически. Работы, начатые **до 1.2.0**, не имеют совместимого checkpoint — для них возможно лишь сохранение ранее выведенных TXT/SRT.

Для контроля целостности используются атомарная замена JSON/TXT/SRT и `fsync` записанных данных, однако абсолютную гарантию при физическом повреждении накопителя дать нельзя. Разделение на минутные блоки может слегка менять качество/границы фраз по сравнению с непрерывным распознаванием. Небольшое перекрытие обеспечивает контекст соседних блоков.

## Параллельное распознавание и прогноз оставшегося времени (1.3.0)

По умолчанию AudioText Studio 1.3.0 использует **2 параллельных обработчика** (одно общее представление модели Whisper), а на CPU ограничивает их вычислительные потоки, чтобы оставить примерно **20% запаса** под другие задачи Windows. Это **мягкая цель**, а не гарантированное ограничение системной нагрузки: интенсивные вычисления и декодирование могут временно превысить её. Программа измеряет загрузку с помощью `psutil` и сокращает подачу новых блоков при высокой загрузке. Запущенные блоки не прерываются, а фоновый рабочий процесс получает пониженный приоритет в Windows (кроме режима fast).

В параметрах можно выбрать **balanced / quiet / fast**, желаемый запас **15/20/25%** и **число обработчиков 0–4** (`0` означает автоматический подбор). Для NVIDIA GPU по-прежнему нужны корректно установленные CUDA 12 и cuDNN 9. Параллельность на GPU может не ускорять обработку при нехватке видеопамяти.

В строке прогресса отображается **«Осталось: ≈ N мин / H ч M мин»**. Оценка появляется после первого успешно обработанного блока и уточняется по фактической скорости обработки. Она не является гарантией: при переключении на другую программу, изменении загрузки или модели время может изменяться.

**Совместимость:** контрольные точки, сохранённые AudioText Studio 1.2.0, продолжают работать — ранее подтверждённая непрерывная часть распознаётся не повторно. Новые версии сохраняют также готовые блоки, завершившиеся не по порядку. TXT/SRT выводятся отсортированными по временным меткам.

## Использование установленного приложения

1. Откройте AudioText Studio через меню «Пуск».
2. Выберите видео/аудиофайл.
3. Выберите режим обработки и модель (small рекомендуется как баланс скорости и качества).
4. Нажмите «Начать обработку».
5. После завершения откройте папку «Результаты_распознавания» или выбранную папку.

### Форматы и особенности

- Первая аудиодорожка извлекается через **FFmpeg**, который входит в сборку.
- TXT содержит таймкоды. SRT подходит для VLC и других видеоплееров.
- Для обработки больших файлов нужны свободное место и оперативная память; `medium` и `large-v3` на CPU могут работать очень долго.
- Остановка прерывает дочерний процесс. Если уже были записаны фразы, частичные TXT/SRT останутся в папке.
- Прогресс основан на времени обработанного фрагмента и может двигаться неравномерно. Загрузка модели может не показывать процент.
- Разрешение на запись в папку результатов обязательно.
- Кодовая подпись для установщика не предусмотрена, поэтому Windows SmartScreen может показывать предупреждение при первом запуске самосборного `.exe`. Не отключайте системную защиту ради запуска файлов неизвестного происхождения.

## Безопасность и данные

- Для извлечения аудио и транскрипции медиа остаются на вашем компьютере.
- В первый раз приложение загружает выбранную **модель** с Hugging Face. Оно не загружает ваши аудио-/видеозаписи для обработки.
- Пользовательские настройки — `%LOCALAPPDATA%\AudioTextStudio\settings.json`.
- Обновление модели и библиотеки приложения не происходит автоматически.
- **Не устанавливайте и не запускайте** случайные EXE из сомнительных источников; собирайте установщик из данного исходного проекта или доверенного собственного репозитория.

## Диаризация говорящих — версия 1.4.0 (дополнительный модуль)

Это **разметка текста**, а не физическое разделение аудиодорожек. По умолчанию выключена.
В блоке **«05 ГОВОРЯЩИЕ»** включите «Определять говорящих». Выберите **auto** или точное количество 2–12. По умолчанию диаризация выполняется на CPU (отдельно от настройки GPU для Whisper).

**Требования для первого запуска:** Python 3.12 (64-bit), место на диске для PyTorch и pyannote, интернет для первого скачивания модели, аккаунт Hugging Face, принятые условия использования модели [pyannote/speaker-diarization-community-1](https://huggingface.co/pyannote/speaker-diarization-community-1) и персональный **Read**-токен, созданный в [Hugging Face Settings → Access Tokens](https://huggingface.co/settings/tokens). Введите токен в поле приложения. Он не сохраняется в settings.json и не загружается вместе с аудио на сервер: используется только для доступа к весам модели. Не отправляйте токены другим людям.

Приложение при необходимости создаёт отдельное виртуальное окружение `%LOCALAPPDATA%\AudioTextStudio\speaker-env` и устанавливает `pyannote.audio>=4,<5`. Это может потребовать большого объёма скачивания и значительного места на диске. Установщик AudioText Studio по-прежнему работает без Python **для обычной расшифровки**; Python 3.12 нужен только для дополнительного анализа говорящих. Доступность CUDA для pyannote зависит от отдельной установки PyTorch и драйверов; начните с CPU.

При включении опции Whisper сначала сохранит исходный TXT/SRT, затем запустит pyannote по всей аудиозаписи. Результат создаётся в **отдельных** файлах `*_speakers.txt`, `*_speakers.srt` и `*_speakers.json`. Исходные TXT/SRT не меняются. В UI можно выбрать **«Голоса в готовом TXT…»**, указать исходную аудио-/видеозапись и ранее созданную расшифровку, чтобы не повторять Whisper. Кнопка **«Переименовать голоса…»** изменяет имена в отдельных TXT/SRT по метаданным JSON без повторного запуска модели.

Завершённый глобальный анализ сохраняется в `.audiotext-checkpoints/*-turns.json` и повторно используется для того же исходного файла и числа голосов. Если сама модель прервана посередине, отдельные промежуточные стадии глобального pyannote пока не восстанавливаются: повторяется только анализ голосов, **не** уже завершённая транскрипция. ETA для pyannote приблизительный; при установке модели и в начале анализа точной оценки нет.

На записи с наложением голосов, шумом или плохим качеством возможны ошибки. Каждая фраза Whisper относится к голосу с максимальным временным перекрытием; если пересечения нет, ставится «Говорящий не определён». Эта процедура не подтверждает реальные личности участников.
